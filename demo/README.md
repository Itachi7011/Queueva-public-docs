# Demo

This folder is a placeholder for demo assets. Recommended approach:

- **Don't commit video files here** (GitHub isn't a great video host, and
  large files bloat the repo). Instead:
  1. Upload the demo video to YouTube (unlisted or public) or Loom.
  2. Replace the placeholder links in the main [`README.md`](../README.md)
     under **Demo video** and **Live demo** with the real URLs.
  3. Optionally drop a static thumbnail image here (`demo-thumbnail.png`)
     and link it to the video in the README, e.g.:

     ```md
     [![Watch the demo](./demo/demo-thumbnail.png)](https://youtu.be/your-video-id)
     ```

## Suggested demo video structure (2–4 minutes)

1. **Hook (10s)** — the problem: local service businesses juggle
   spreadsheets, phone calls, and no-shows. Show the public shop page.
2. **Booking flow (30s)** — book an appointment as a client, showing real
   live availability and instant confirmation.
3. **AI assistant (30–40s)** — your strongest differentiator: text the
   shop's number and book/cancel/check availability entirely over
   SMS/WhatsApp, live.
4. **Owner dashboard (40–50s)** — a quick tour: appointments updating in
   real time, a membership plan, a gift card sale, and the waitlist
   filling an open slot automatically.
5. **Payments & automation (20s)** — a real Stripe checkout, then a
   rebooking-nudge or win-back email as an example of the automation
   engine working without manual follow-up.
6. **Close (10s)** — call to action: live demo link / contact for access.

Keep it screen-recording + voiceover, no slides — investors and technical
evaluators respond better to a real working product than a deck.
